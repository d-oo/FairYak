`docs/design/`에 있는 디자인 zip(README.md + `*.dc.html` + 스크린샷으로 구성된
"design_handoff" 번들)을 이 리포지토리에 구현할 때 따르는 절차입니다. 시안마다
구체적인 요구사항(인터랙션을 얼마나 실제로 동작하게 할지, 데이터를 실제 Supabase에
붙일지 등)은 매번 다르므로 여기엔 넣지 않습니다 — 아래는 매번 반복해야 하는 "일하는
방식"만 정리한 것입니다. 지금은 기존 디자인을 새 시안으로 전면 교체하는 중이라
`CLAUDE.md`의 "스타일링" 절(기존 헥스 폐기, 새 색은 토큰으로)을 함께 따릅니다.

## 1. 구현 전에 원본을 통째로 읽는다

압축을 풀고 README.md와 `.dc.html`을 **먼저 전부** 읽습니다. 스크린샷이나 README의
글로 된 설명만 보고 근사치로 스타일 값(px, 색상, 그림자)을 짜지 마세요 — `.dc.html`의
인라인 `style`이 실제 정답이고, 나중에 값이 달라 여러 파일을 다시 고치는 이중 작업을
막아줍니다. README의 "Fidelity"/"Design Tokens" 절이 픽셀 단위 재현을 요구하는지,
값을 단순화해도 되는지부터 확인하세요.

## 2. 기존 컴포넌트·토큰 재사용과 파일 위치를 먼저 정한다

- 파일 위치는 Next.js App Router 컨벤션을 따릅니다. 특정 라우트에서만 쓰는 컴포넌트는
  그 라우트 옆 `_components/`(예: `src/app/dashboard/_components`,
  `src/app/dashboard/meetings/_components`)에 두고, 여러 라우트가 쓰게 되면 공통
  부모 라우트의 `_components/`로 올립니다. 쓰는 곳이 하나뿐이면 미리 올리지 않습니다.
- 상태·이벤트 핸들러·브라우저 API가 필요한 부분만 `"use client"` 컴포넌트로 두고,
  나머지는 서버 컴포넌트로 유지합니다. 시안 하나를 통째로 클라이언트 컴포넌트로
  만들지 마세요.
- 시안의 마크업이 기존 컴포넌트(모달, 탭 바, 캘린더, 주소 검색 등)와 같은 역할이면
  새로 만들지 말고 그 컴포넌트의 모양을 시안대로 바꿉니다 — 데이터 흐름·Supabase
  호출·Realtime 구독 같은 동작은 건드리지 않고 겉모습만 교체합니다.
- **색은 기존 헥스(`#0d1f2d`, `#4ecdc4` 등)에 맞추지 않습니다** — 폐기 예정입니다.
  시안 색은 `src/app/globals.css`의 `:root`에 토큰으로 정의하고 `@theme inline`에서
  `--color-*`로 참조만 추가해 유틸리티 클래스로 씁니다. 같은 값의 새 토큰이 이미
  있으면 그걸 재사용하고, 이름은 값이 아니라 역할로 짓습니다(`--primary`, `--surface`
  등). 그림자·그라데이션 같은 복합 값은 여러 곳에서 쓰일 때만 토큰으로 등록하고, 한
  곳에서만 쓰이면 인라인 style로 둡니다. 단, `:hover`/`:active` 같은 의사 클래스가
  필요한 다중 그림자 값은 인라인 style로 표현할 수 없으므로 한 곳에서만 쓰여도
  토큰으로 등록해야 합니다(콤마가 있는 `shadow-[...]` 임의값 클래스는 무시될 수 있음).
- 시안으로 옮기는 화면 안의 기존 헥스는 새 토큰으로 바꾸고, 이번에 다루지 않는 화면의
  헥스는 그대로 둡니다.

## 3. 제품/데이터 관련 결정은 추측하지 않고 물어본다

시안 자체에 답이 없는 것들 — 인터랙션을 얼마나 실제로 동작하게 만들지, 데이터가
실제 Supabase인지 목업인지, 새 화면이 로그인이 필요한지(보호된 레이아웃 아래에 둘지),
기존 기능(초대·나가기·추천 결과 등) 중 시안에 없는 걸 빼도 되는지, 외부 API(Kakao,
ODsay) 정책·제약에 걸리는 부분이 있는지 — 은 짐작하지 말고 사용자에게 확인합니다.
리서치가 필요한 부분은 먼저 조사해서 근거와 함께 제안하세요.

## 4. 픽셀 단위로 정확히 재현한다

색상/그림자/타이포/간격은 시안 원문 값 그대로 옮깁니다. 표준 Tailwind 스케일과
정확히 일치하면 표준 유틸리티 클래스를 쓰고, 안 맞으면 임의값(`[...]`) 문법을
그대로 씁니다 — 어색해 보여도 반올림하지 마세요.

## 5. 구현 후 검증한다

`npm run build`/`npm run lint`를 실행하고, 가능하면 `npm run dev`(3000번)로 실제
화면을 띄워 시안 스크린샷과 직접 비교합니다. 대시보드 아래 화면은 로그인이 필요하니,
직접 확인할 수단이 없으면 사용자에게 화면 확인을 요청하세요.
